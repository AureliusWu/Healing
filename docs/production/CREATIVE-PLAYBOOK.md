# 剧情与美术协作方法 v1.0.0

适用 Rain、NetLove、Healing，制作契约 v1.2.0。本文、场景模板及 vn-creative 工具在三仓保持同一版本与哈希；各作品保留自己的引擎、人物、年龄设定、剧情和存档身份。

## 场景精修

以一个现场问题为单位：哪张稿纸少了字、谁迟到、哪条消息没有回。列出人物想完成的事、此刻知道的事、手边的东西，再修对话和前后动作。读完一个完整分支再看合流，检查物品与知识有没有提前跳转。

重复的抽象判断可换成具体动作。“留下空间”可以落到把笔绑在书架边、背上书包按时离开；“相遇有意义”可以落到采购清单上仍留着朋友改过的错字。必要的内心句保留，人物的口语、干涩幽默与脾气分别处理，结尾不额外替读者总结。

精修前从原生剧情捕获 snapshotStory 基线；精修后用 auditRevision 核对场景顺序、台词身份/段落数量、选择效果与去向、条件路由及已录音句。允许正文和表现数据修改，禁止悄悄移动旧档位置。Rain 的 17 句录音在本轮逐字锁定；改录音句时另开声音制作任务，生成、试听、字节与正文比对后再更新清单。

Healing 从实际 TypeScript 剧情导出基线，保留第一章 v0.1.6 固定夹具；另外两仓直接读唯一 JSON。工具检查不能取代原生状态路线遍历、人物动机审阅、真人试听或阅读计时。

## 表情与画面

以已有认可角色为参考，固定发型、发夹方向、衣服、道具、站姿和比例。一次只修一项，背景、人物图集与事件 CG 分别制作。保存完整实际请求、参考、生成源图、运行图、尺寸、alpha 与哈希，禁止用滤镜冒充表情。

NetLove 采用 Healing 的六表情与按台词重建方法：作者明确注解表情，旁白继承上一拍，读档与回看按原段落重新计算，不新增存档字段。匿名聊天和纯声音通话的 noSprite 保留，避免提前揭示人物或把消息人物变成在场人物。

标称 3×2 不保证生成结果等分。加工脚本先找真实透明行间空隙，再测量每行三个主体；取格适配画布边缘，拒绝越界和邻格串入，只转换编码、记录坐标，保留原像素与透明通道。validateFrames 独立核对实际画布边界。仍需在真正的背景、横屏和竖屏上查看脸、头、手、鞋和道具。

低 alpha 预览可能放大隐藏的 RGB 杂色，应在实际背景合成后复核，不能凭黑底预览删除边缘。事件 CG 必须对应确切场景与物品：Healing 的漏句样张来自同一文印室参考，不叠加立绘；Rain 小店保留空间、夜色和杯子，简化颗粒与过度反光。新资源要真正进入游戏、离线缓存与按阅读解锁的回忆。

## 三仓回馈

| 来源 | 可复用内容 | 接收 |
| --- | --- | --- |
| Healing | 六表情、旁白继承、原段落恢复与表情图集方法 | NetLove 接入；测量修正回馈 Healing |
| Rain | 录音句锁定、版本化 Prompt、源图/运行图追溯 | 三仓修订兼容检查；语音配方供独立后续 |
| NetLove | 匿名/通话可见性、实际透明行间空隙与邻格检查 | 共用文档、模板与工具同步 |

每次回馈记录来源提交、采用文件、目标侧实际验证和限制。专用人物、CG、声音身份列为 project-only；通用包导出有相应许可的工具、模板与制作方法，不能把代码 MIT 自动套到美术上。共享哈希由 REUSE-MANIFEST 锁定，先检查实际字节，再导出。

## 验收与续作

运行共用工具、素材校验、原生剧情与存档检查、字体覆盖和生产构建，再检查实际画面、隐藏恢复、旋转、离线重开和读档。Windows 源码、实际 EXE 与公开 PWA 分开留证；旧版成功记录不充当新版证据。

每批工作结束或即将等待外部验收前，把源文件与资源写入可回读的 Git 检查点，并记录提交/树 SHA；临时工作区和跨轮内存不作为唯一断点。恢复时核对哈希，复用已生成素材，继续剩余验收。
