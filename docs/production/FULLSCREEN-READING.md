# 全屏浮层阅读规范

本规范记录《湿性愈合》从 2026-10-07 起采用的阅读画面结构，优先级高于 `docs/PRODUCTION.md` 中早期“场景与阅读区完全分行、不叠加”的旧布局描述。后续界面修改应保持以下契约，除非用户明确要求再次改变。

## 目标结构

- 故事背景与立绘组成一个覆盖整个可视窗口的画面层；桌面端与横屏 PWA 都不保留顶部纸张栏或画框留白。
- 阅读 UI 只保留在画面下部：说话人、正文/选项、存档、回看、自动、快进、隐藏、返回、全屏、设置与透明度控制共同构成一个半透明操作层。
- 原顶部章名、场景名、地点、时间不再常驻占据独立高度；需要的功能键移入底部操作层。
- 底部阅读层默认透明度为 72%，可调范围 35%–95%。对话框和并入其中的功能键共用同一透明度变量；用户选择保存在 `moist-healing:v1:dialogue-opacity`。
- 隐藏界面时，所有阅读浮层与透明度控制一起消失，并继续保持“暂停自动/快进、恢复不推进剧情”的既有行为。

## 实现策略

当前实现保留原来的语义 DOM 与逻辑网格，以减少对键盘、旋转、存档、自动阅读和既有测试的影响；视觉层通过 `src/fullscreen-reading.css` 重排：

- `.scene-frame` 视觉上铺满 `100vw × 100dvh`，背景使用 `object-fit: cover`。
- `.story-controls` 保留逻辑上的底部行，但自身透明；真正的 `.reading-panel` 使用半透明背景和轻度模糊，因而看起来直接浮在画面上。
- `.game-header` 本身压缩为 0 高度，原来的返回、全屏、设置按钮固定到阅读层底部，不再形成顶部条。
- `src/ReadingOverlayOpacity.tsx` 独立负责透明度状态、持久化和调节控件，避免改动剧情存档 schema。

这种方式的可复用点是：当“视觉上全屏叠加”和“既有逻辑/测试结构”发生冲突时，优先保留语义结构，通过独立视觉层重排，降低无关回归范围。

## 响应式要求

- 1440×900 / Windows：背景铺满窗口；底部浮层居中，最大宽度 1180px；所有功能键位于浮层内部视觉范围。
- 568×320、640×360、844×390、915×412：正文与功能区允许压缩，工具栏可横向滚动，但不得产生页面级横向溢出。
- 竖屏 PWA：背景仍使用 cover，角色允许更宽的视觉占比；横屏提示可以作为临时提示出现，不改变剧情与存档。
- 隐藏界面后画面必须保持完整窗口尺寸。

## 验证要点

每次改动此结构至少检查：

1. 背景实际覆盖整个窗口，底部没有纸色空白区。
2. 返回、全屏、设置、存档、回看、自动、快进、隐藏都仍可操作。
3. 调整透明度后对话层与并入的功能键同时变化，并在刷新/重新进入后保留。
4. 选择分支、结局卡片和长文本仍限制在底部浮层内，不撑出窗口。
5. `H` 隐藏、轻触恢复、自动暂停、旋转、离线重开与旧存档兼容行为不变。
