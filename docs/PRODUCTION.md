# 制作规范

此文档固定《湿性愈合》的审美、资源与交互约定。每次制作把实际有效的办法补到这里，具体问题与证据写入 [迭代记录](production/ITERATIONS.md)。当前美术基准为 v0.1.4；阅读界面遵循 [全屏浮层阅读规范](production/FULLSCREEN-READING.md)，人物资源遵循 [角色美术规范](production/CHARACTER-ART.md)。

## 美术方向与参考

目标是清新、克制的二维校园视觉小说：线稿明确、色块干净、阴影简洁，保留雨后的湿润感与靠近他人的犹豫。参考下表所列作品的官方商店画面，观察结果用于制定本项目规则。

| 官方参考 | 画面观察 | 在本项目中的取舍 |
| --- | --- | --- |
| [三色绘恋](https://store.steampowered.com/app/668630/?l=schinese) | 人物眼睛、发束与轮廓高度动画化，明暗按大块组织 | 保留人物识别特征，简化头发、皮肤和衣褶，避免肖像写实 |
| [恋爱绮谭：不存在的夏天](https://store.steampowered.com/app/1345740/?l=schinese) | 官方截图中的人物线条清楚，平涂色面和少量高光让表情易读 | 统一两位角色的线条、眼睛和上色方式，控制背景纹理密度 |
| [他人世界末](https://store.steampowered.com/app/1225780/) | 室内场景与角色依靠清晰边界、较大的颜色面分层，操作条很简洁 | 缩减常驻信息；结合用户的画面优先要求，将正文与选项移出场景 |

上表是基于截图的设计判断，不是三部作品的制作规定。参考的是视觉组织方式，游戏中的人物、服装、场景、文字与界面由本项目制作。

## 画风与人物契约

| 项目 | 固定规则 |
| --- | --- |
| 线条 | 纤细清晰，重要轮廓可读；不使用写实照片边缘或模糊皮肤纹理 |
| 上色 | 平涂为主，两至三级明暗，头发用成组色面与少量高光 |
| 背景 | 简化建筑、树冠和地面反光；雨后感由色温与绘制的光影表达 |
| 主色 | 纸色 `#f7f5ed`、深绿文字 `#344e3e`、薄荷绿、灰蓝、少量暖珊瑚 |
| 校服 | 宽松米白/墨绿运动夹克、白色圆领上衣、藏蓝运动裤 |
| 林见夏 | 深色齐肩短发、浅绿矩形发夹、棕眼、收敛的微笑；双手抱笔记本 |
| 陈知遥 | 栗棕高马尾、米白发圈、棕眼、明亮微笑；抱旧校刊 |
| 许棠 | 深棕低马尾、深色发圈、琥珀棕眼；相机与校刊样张 |

每次新增人物表情或动作，都保留发型、配色、头身比例和服装结构。三位角色必须在同一角色资料页中一起核对风格，再各自进入实际剧情复验。先确认眼睛、轮廓、手与道具，再看细节；不可用 CSS 滤镜冒充美术重绘。

## 场景与阅读区

背景与立绘铺满整个窗口。剧情正文、选项、结局与必要操作按钮统一进入下部半透明阅读层，透明度可调整并持久化。完整响应式约定以 [全屏浮层阅读规范](production/FULLSCREEN-READING.md) 为准。

隐藏界面暂停自动 / 快进；首次轻触、`H` 或 `Esc` 恢复原段落，不推进也不替玩家选择。横竖屏切换不改变进度。桌面全屏由玩家操作触发，手机网页使用页面内沉浸模式。

## 素材制作与归档

1. 从人物契约与场景用途形成单一素材规格。背景、三视图与运行立绘分别生成。允许角色专用透明表情图集，并记录真实采样范围；不从带背景或 UI 的拼图中抠图代替立绘。
2. 使用内置图像生成工具重绘或生成；编辑现有角色时先查看原图，注明身份、服装与姿势不变量。角色要求真正透明的 alpha。
3. 保存最终采用的完整提示词到 [ART.md](prompts/ART.md)，注明输入资源对应的 Git 版本。未采用的失败版本写经验即可。
4. 人工检查头顶、手、道具、线稿、透明边缘与画风；使用格式脚本转换为项目 WebP。
5. 更新 [资源清单](production/ART-ASSETS.json)，记录尺寸、透明范围、文件大小与 SHA-256。资源稳定命名为 `public/art/*.webp`，历史版本由 Git 保留。
6. 在真实游戏里同时验收背景、立绘、文字与选择。只看素材大图不足以确认角色比例或阅读体验。

格式转换只改变编码，保留原图像素尺寸与透明通道：

```bash
python -m pip install Pillow
python scripts/prepare-art.py path/to/campus.png public/art/campus.webp --kind background --replace
python scripts/prepare-art.py path/to/lin.png public/art/lin.webp --kind sprite --replace
```

脚本检查背景 16:9、最低分辨率、立绘真实透明角、透明比例和头/手边距，并逐像素确认 alpha 在 WebP 编码后保留。背景使用质量 92；立绘无损编码。`--replace` 要在人工认可改图后使用。脚本不能判断手部结构、审美或角色身份，这些仍需查看。

## 字体、离线与发布

中文字体自托管，新增界面/剧情文字时重建子集并检查中文字形覆盖。使用已许可的 Noto Serif SC TTF：

```bash
python -m pip install 'fonttools[woff]' brotli
python scripts/subset-font.py path/to/NotoSerifSC.ttf
```

源字体与许可地址见 [ART.md](prompts/ART.md)。输出固定 400 字重，字体原始大文件无需入库。CSS 使用的字重应与文件一致。

修改后执行 `npm test`、`npm run build` 及相关 Playwright 检查；发布前完整复验。画面相关检查必须含 1440×900、412×915、568×320、640×360、844×390、915×412。验证全窗口背景、底部浮层与透明度、关键头部和手部可见、所有选择可操作、隐藏界面不推进、旋转/离线/旧存档可续读。

更改版本时同时更新 `package.json`、`package-lock.json`、版本说明和预览。主分支完整 CI 通过后发布双端；Windows 源码与实际 ASAR 启动、线上 PWA 离线重开都必须得到实际结果。发布后记录提交、流程网址、下载与截图证据，不能将“配置存在”写成“发布成功”。

## 每次制作的沉淀

完成时检查这四项，并把结果写入迭代记录：

| 内容 | 应留下的文件 |
| --- | --- |
| 经验证的规则 | 本文或剧情/架构文档中的明确约定 |
| 可复用的素材/方法 | 最终提示词、资源清单、脚本、组件与兼容契约 |
| 实际问题与修复 | 问题触发条件、采用的办法、避免复发的检查 |
| 完成证据 | 版本说明、实际预览、测试与双端发布记录 |

不把一次性的环境路径、凭据或未经验证的猜测固定为项目依赖。一次制作至少更新相关条目；已经固定的规则无需重复抄写。
